# QA 检查清单

## 必过项（必须全部勾选）

- [ ] 是 16:9 横版比例。
- [ ] 背景是纯白色底，没有纸张纹理、噪点、渐变或阴影。
- [ ] 画面中包含固定人设小男孩（圆黑框眼镜、刺刺短发、深蓝上衣），且正在承担核心动作，而不是静态装饰。
- [ ] **画面上没有出现「希扬」「Xiyang」或任何角色名、名牌、头顶署名。**
- [ ] 角色戴着大圆黑框眼镜，留着刺刺的黑色短发，穿着深蓝色上衣。
- [ ] 画面简洁干净，主体只占中央的 40%-60%，周围留出至少 35% 的纯白空间。
- [ ] 每次生成均使用结合文章内容新设计的物理隐喻，没有生硬照搬以往案例。
- [ ] 一张图只讲一个核心逻辑，绝不贪多。
- [ ] 中文手写字标注少而精（一般最多 5-8 处，每处 2-8 个字），字体清晰易读。
- [ ] 暖橙黄色只用于发光的灵感灯泡、主流程路径箭头、以及被希扬操作点亮/浇活的线条。
- [ ] 红色仅用于痛点、阻断、警示和负面结果。
- [ ] 蓝色仅用于辅助批注、脑内想法或第二层系统反馈。

## 失败信号（出现任意一项必须重做或局部修改）

- [ ] 画面上写了「希扬」「Xiyang」或角色名标签、名牌、头顶署名。
- [ ] 左上角出现了类似“Workflow / 流程图 / 避坑指南”等显式的大分类标题。
- [ ] 希扬被画成了圆润、可爱的商业吉祥物，或者带有嘴巴、红晕、动物耳朵等复杂面部特征。
- [ ] 画面看起来像正式的 PPT 信息图、课程课件或教条的流程图（过多的标准块和网格线）。
- [ ] 节点和关系过多，箭头在画面中乱飞，导致信息密度过大。
- [ ] 标注文字变成了长段的说明文字。
- [ ] 出现了真实的 App 界面截图或高科技 UI 风格。
- [ ] 画面太普通死板，缺乏怪诞和创意隐喻。
- [ ] 拼写或中文手写字错字严重或极难辨认。

## 常见问题迭代方法

- **画面没有温度**：增加手绘线条的微颤感（wobbly lines），确保不使用完美圆形或直线；让希扬的动作变得更具物理真实感（如吃力托举、认真浇灌）。
- **文字错乱**：通过局部编辑修复文字；或重新生成时在提示词中减少中文标注数量。
- **信息过载**：删减非核心步骤，只留一个主流程和 3 个左右最核心的批注字。
- **色彩杂乱**：将大部分彩色标记替换为黑色，仅在最核心转折处保留橙色、红色或蓝色。
