# 希扬创意手绘正文配图

## 核心定位

为中文文章设计和生成 16:9 横版正文配图。目标是将文章中的核心逻辑、关键判断、流程、结构或隐喻，转换成一张简洁、温暖、富有启发性、可读但不显沉闷的手绘解释图。

默认视觉 IP 是“希扬”：一个戴大圆黑框眼镜、留刺刺黑色短发、身穿深蓝色T恤与卡其色短裤的Q版简笔手绘小男孩。它的表情平静、好奇，专注于做一些“连接、托举、点亮、浇灌”等优化或探索系统的动作。希扬必须成为画面的动作主体，拒绝成为纯装饰性的背景。

**画面上只出现人物形象，不出现 IP 名字。**「希扬」「Xiyang」等名称仅用于 Agent 内部沟通与 prompt 描述角色外形；**禁止**在成图上写角色名、名牌、头顶标签或任何形式的 IP 标识。图上可见的中文批注只能是**内容隐喻**（如「方便」「串起来」），不能是角色署名。

## 参考规范文件

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：风格 DNA、颜色、文字、禁忌。
- `references/xiyang-ip.md`：希扬 IP 的形象、性格、动作库和禁忌。
- `references/composition-patterns.md`：结构类型、原创隐喻方法和反复刻规则。
- `references/prompt-template.md`：单张生图提示词模板。
- `references/qa-checklist.md`：生成后检查和迭代规则。
- `assets/examples/`：只作低频视觉校准，不进入默认生成路径。不要照抄这些案例的构图、物件或标注。

## 工作流

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容。提炼：

- 核心观点是什么
- 哪些段落承担认知转折
- 哪些内容适合用图解释
- 哪些地方只适合文字，不需要图

不要平均配图。优先选择“认知锚点”，例如：核心判断、两个断点、输入输出闭环、分流、前后对比、一鱼多吃、承接路径、常见坑、角色状态变化。

### 2. 输出配图策略

如果用户只是说“分析怎么配图 / 思考哪些地方需要配图”，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 希扬在图里做什么（动作描述，非画面文字）
- 建议元素
- 建议中文标注词（**仅限内容批注，不含角色名**）

默认 4-8 张。文章很短时 1-3 张；长文也不要轻易超过 9 张。够用就好，避免把正文做成画册。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，不要停下来等确认；**调用 [generate-image](../generate-image/SKILL.md) 的 `scripts/generate.py`** 生图。不要把多张图拼在一张里。

每张图只讲一个核心结构。提示词必须包含：

- 16:9 横版中文正文配图
- 纯白背景
- 彩色手绘线稿
- 少量红色/橙色/蓝色中文手写批注（**内容隐喻，不写角色名**）
- 大量留白
- 固定人设的小男孩作为动作主体（刺刺短发、圆黑框眼镜、深蓝 T 恤、卡其短裤、光脚），表现出安静、温和且专注的状态
- **禁止**在画面上写「希扬」「Xiyang」或任何 IP 名字标识
- 禁止 PPT、商业插画、幼稚可爱、复杂架构、左上角类型标题

不要复刻过往案例。案例只提供风格密度和小黑参与方式，不能直接复用“传送带断点 / 小黑拉线 / 素材鱼 / 盖章工具箱 / 常见坑路径”等已有构图，除非用户明确要求复刻某张图。每次都要从当前文章重新发明一个奇怪但成立的隐喻。

### 4. 检查与迭代

生图后对照 `references/qa-checklist.md` 进行检查。如出现以下情况，需重新生成或进行局部修改：
- 画面上出现了「希扬」「Xiyang」或角色名名牌、头顶署名标签。
- 希扬沦为纯背景装饰。
- 画面过于拥挤或过于像标准 PPT 架构图。
- 文字大段堆砌或拼写杂乱。
- 希扬形象画得过于幼稚或像市面上的常见吉祥物。
- 出现左上角大标题。


### 5. 保存交付

物理交付时，**遵循 [generate-image](../generate-image/SKILL.md) 中的 assets 路径与命名规范**：
* 目标子目录：`apps/share-portal/public/share-tutorial/assets/<分类文件夹>/<文章主名>/`
* 命名规则：直接命名为 `01.png`, `02.png` 序号，保持目录清爽。
* 并在 markdown 文件里以相对路径 `../assets/` 方式进行嵌入引用。

## 输出口径

生成前的策略输出要短而准。生成后的交付要包含：

- 生成了几张
- 每张图的用途
- 保存路径
- 哪些图最稳，哪些图是可选

不要长篇解释风格理论；让图自己说话。
